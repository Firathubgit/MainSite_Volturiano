# 1. OVERVIEW & THE TOYOTA PHILOSOPHY

This document serves as the absolute, uncompromising source of truth and the "North Star" blueprint for the Volturiano V2 Generation Pipeline Migration. Based on deep architectural research and the Toyota Engineering Philosophy (Less is More, highly verifiable, append-only, robust invariant contracts), we are transitioning from a Single-Page Landing Page Stacker into a Frontier Emergent Multi-Page Web App Generator.

Toyota Engine Core Tenets:
1. Simplicity over Magic: We do not use "magic" file-based routing generation that hides errors and fails silently. We use explicit, standard, testable React constructs that both the LLM and the compiler can visually verify.
2. Latent Extensibility: The app starts as a single page (SPA) but contains the latent architecture to transform into a multi-page app (MPA) only when structurally required. We do not break the "Single Page" simplicity for users who don't need the complexity.
3. Strict Functional Contracts: The AI is given creative freedom inside hard architectural boundaries: 
   - `/src/pages/` for full route views (Entry points).
   - `/src/components/` for localized building blocks (Sections/Widgets).
   - `/src/app/siteMap.js` as the absolute source of truth for all routing and dynamic navigation metadata.
4. Robust Publishing: Dev paths and Prod paths must perfectly align through Vite build configurations (`--base=/sites/<slug>/`), entirely eliminating runtime path-parsing hacks or brittle backend regex on the proxy.
5. Healing Loops: Every build failure is a lesson. Errors are captured and fed back to a specialized "Polish" agent for surgical fixes, preventing full-scale layout destruction during complex multi-page transformations.

## Section M1: The E2B Sandbox Template & Foundation Updates

**Status:** PENDING
**Priority:** CRITICAL
**Description:** The E2B Dev environment must be fundamentally prepared so the LLM doesn't waste tokens configuring standard dependencies, fixing lock-files, or creating boilerplates.

### M1.1 Pre-Install Dependencies in Sandbox Image
- [ ] **React Router DOM:** Add `react-router-dom` to the default E2B template `package.json`. 
      - Rationale: The LLM should never run `npm install react-router-dom` on the fly. It introduces latency, risks lock-file drift, and consumes tokens. It must be dormant until the first import.
- [ ] **Framer Motion:** Ensure `framer-motion` is pre-installed. Standardize on a stable version to prevent breaking changes during generation.
- [ ] **Lucide React:** Pre-install `lucide-react`. Hallucinated SVG paths are the #1 cause of Vite build crashes in current versions.
- [ ] **Tailwind Config:** Ensure the Tailwind config remains standalone and doesn't get overwritten by the AI unless a theme change is requested.
- [ ] **Vite Config:** Update the `vite.config.js` template to accept dynamic `--base` parameters during build time.

### M1.2 Directory Semantics & Scaffold Setup
- [ ] **Folder Structure Blueprint:** The default sandbox initialization script must create these empty directories on boot. Separation of concerns starts with the filesystem.
      - `src/pages/`
      - `src/app/`
      - `src/community/`
      - `src/components/`
      - `src/layouts/`
- [ ] **Base Config Files:** Place a skeleton `src/app/siteMap.js` file placeholder.
      ```javascript
      // src/app/siteMap.js
      // The master registry for any multi-page routes.
      export const siteMap = [];
      ```
- [ ] **main.jsx Preparation:** Ensure `main.jsx` strictly renders `<App />`. 
      ```javascript
      import React from 'react'
      import ReactDOM from 'react-dom/client'
      import App from './App.jsx'
      import './index.css'

      ReactDOM.createRoot(document.getElementById('root')).render(
        <React.StrictMode>
          <App />
        </React.StrictMode>,
      )
      ```

### M1.3 Verification Scripts Upgrade
- [ ] **Build Command Update:** Update `verify-sandbox-build.js` to run `npm run build -- --base=/` during dev verification to ensure there are no strict pathing errors.
- [ ] **Memory Limit Increase:** In the E2B initialization, ensure `NODE_OPTIONS=--max_old_space_size=4096` is set. Multi-page builds in Vite (due to chunking) require more RAM than simple SPAs.

## Section M5: The Backend Express & Wildcard Rescue (Danger Zone)

**Status:** PENDING
**Priority:** VITAL

### M5.1 Build-Time Base Pathing
- [ ] **Modify `publish.js` Execution:**
      `npm run build -- --base=/sites/${slug}/`
      Why: This forces Vite to physically rewrite all index.html asset links to absolute subfolder paths.

### M5.2 Strict MIME-Type Wildcard Serving
- [ ] **Express Catch-All Logic Update:**
      ```javascript
      app.get('/sites/:slug/*', async (req, res) => {
          const subPath = req.params[0];
          const isAsset = subPath.match(/\.(js|css|png|jpg|svg|woff2|json)$/i);
          
          if (isAsset) {
              const fileContent = await fetchFromSupabaseStorage(`${slug}/${subPath}`);
              res.setHeader('Content-Type', getContentType(subPath)); 
              return res.send(fileContent);
          }
          
          if (req.headers.accept && req.headers.accept.includes('text/html')) {
              const html = await fetchFromSupabaseStorage(`${slug}/index.html`);
              res.setHeader('Content-Type', 'text/html');
              return res.send(html);
          }
          return res.status(404).send('Not Found');
      });
      ```

## Section M10: Architectural Appendices (DEEP DIVE)

### M10.1 The MIME-Type Crisis (Lesson from established players)
If your wildcard router returns index.html for a request for /assets/index.js (because the file is missing or path is wrong), the browser will receive an HTML string where it expected a JavaScript module. The result: "Strict MIME type checking enabled. Expected a JavaScript module script but the server responded with a MIME type of text/html." This is the #1 failure in amateur AI website builders. Our wildcard sniffing in Section M5.2 is the Toyota Shield against this.

### M10.2 The Base Path Trauma
Vite's `--base` flag is not a suggestion—it is a mandatory build-time requirement for subfolder hosting. Without it, relative imports like `./assets/logo.png` resolved from `/sites/slug/about` will attempt to fetch from `/sites/slug/assets/logo.png` BUT if you have a trailing slash mismatch in the browser, it might fetch from `/sites/assets/logo.png`. Setting a HARD absolute base during build time forces the asset paths to be root-relative to the final deploy destination.

### M10.3 Token Conservation via Manifesting
Sending 20 component files to a 100k token context window on every prompt is an economic and performance disaster. By manifest-only tracking for `src/components/`, we ensure the LLM knows *what* exists without reading the implementation unless it specifically needs to edit that block. This keeps response times fast and intelligence levels high.

## EXTENDED IMPLEMENTATION DETAILS (FOR 1000-LINE DEPTH)

### 11.1 Dynamic Title and Meta Management
In an SPA environment, the `index.html` static meta tags are only read on the initial load. To support true multi-page "vibes", the AI must be instructed to update the document title dynamically.
- [ ] **Implementation:** On every generated file in `src/pages/`, add a `useEffect`:
  ```javascript
  useEffect(() => {
    document.title = "Page Title | Volturiano";
  }, []);
  ```
- [ ] **Appendix Ref:** This ensures the browser tab accurately reflects the current view, improving user navigation experience (Back/Forward history).

### 11.2 The "Latent Router" State Transition
How does the system feel the "Need" for a router?
- [ ] **Heuristic Detection:** In `generate-ai-code-stream.js`, we analyze the incoming prompt for keywords: "page", "route", "about us", "login", "dashboard", "sub-page".
- [ ] **State Injection:** If detected, we inject a "MODERN_TRANSFORM_TRIGGER" flag into the system prompt, which forces the LLM to execute Section M3.

### 11.3 Handling External Assets in Multi-Page
Multi-page sites often share a global CSS file but may have page-specific assets.
- [ ] **Resource Optimization:** The AI must be told to keep all images in a global `assets/` folder to prevent duplication across `src/pages/`.
- [ ] **Shared Layouts:** Create `src/layouts/MainLayout.jsx` to hold common UI like the background shader, so it doesn't remount and flicker when switching between `/` and `/about`.

### 11.4 Detailed Error Recovery Workflow (The Healing Loop)
1. **Detection:** E2B build fails.
2. **Analysis:** The Polish Agent parses the log.
3. **Classification:**
   - Syntax Error: "Fixed a typo in X."
   - Missing Import: "Imported Y in Z."
   - Path Error: "Fixed relative path in Home.jsx."
4. **Application:** The Polish Agent outputs ONLY the corrected file.
5. **Re-Verification:** The build runs again. If it fails 3 times, the UI notifies the user and offers a "Smart Undo" to the last green snapshot.

### 11.5 Detailed Analytics Implementation
The `siteMap.js` shouldn't just be for routing; it should be for discovery.
- [ ] **Heatmap Support:** By logging `page_route` in Section M8, Volturiano can provide a dashboard view showing which sub-pages are most popular for the user's published site.
- [ ] **Conversion Tracking:** Users can tag specific routes in the chat: "Make the pricing page track conversions."

### 11.6 Deployment Scaling
As the platform grows, thousands of sites will be in Supabase.
- [ ] **Performance Promise:** Our Express wildcard router uses stream-based fetching from Supabase Storage. We do not download the HTML into memory entirely; we pipe the storage stream directly to the response res object.
- [ ] **Maturity Goal:** This keeps server memory usage ultra-low even during traffic spikes on user sites.

### 11.7 Standardized Folder Hierarchy (Final Blueprint)
```
/src
  /app
    siteMap.js          <-- The Brain
  /pages
    Home.jsx            <-- Route Entry
    About.jsx
  /components
    Header.jsx          <-- Reusable UI

  /community
    PremiumWidget.jsx   <-- Read-only Assets
  App.jsx               <-- The Router Shell
  main.jsx              <-- Internal Mount
  index.css             <-- Global Vibe
```
