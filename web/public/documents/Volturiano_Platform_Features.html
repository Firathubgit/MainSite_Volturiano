Section 01

Platform Architecture & Infrastructure

1.1 Frontend Framework
  • React 18+ with Vite for sub-second hot module replacement.
  • React Router v6 with route-level code splitting and lazy loading.
  • Feature-sliced architecture: each module is self-contained with its own components, API layer, store slice, and scoped CSS.
  • CSS Modules + PostCSS for zero-collision component styling.
  • Framer Motion for declarative scroll-reveal, page transitions, and micro-interactions across the entire UI.
  • Full progressive web app (PWA) readiness with service worker hooks.
1.2 Backend & Data Layer
  • Supabase (PostgreSQL 15) as the single source of truth.
  • Row-Level Security (RLS) on every table — no data leaks by design.
  • Supabase Auth with email/password, magic links, and social OAuth providers.
  • Supabase Realtime subscriptions for live dashboard updates, garage sync, and inventory changes pushed to every connected client instantly.
  • Supabase Edge Functions (Deno) for server-side logic: PDF generation, Stripe webhooks, email dispatch, AI proxy, and scheduled jobs.
  • Supabase Storage CDN with signed URLs for renders, 3D models, documents, and user-uploaded assets — globally distributed.
1.3 State Management
  • Zustand stores with fine-grained subscriptions (no unnecessary re-renders).
  • Dedicated stores: userStore, uiStore, configStore, garageStore.
  • Optimistic updates with automatic rollback on server failure.
  • localStorage persistence for offline-capable core features.
  • Session management with automatic token refresh.
1.4 CI/CD & Deployment
  • GitHub Actions workflows for automated testing, linting, and deployment.
  • Vercel/Netlify frontend hosting with edge CDN and preview deployments.
  • Supabase CLI for database migrations with rollback capability.
  • Lighthouse CI for enforcing performance budgets on every pull request.
  • Zero-downtime deployments with atomic rollouts.
1.5 Error Handling & Monitoring
  • Global and route-level React Error Boundaries preventing full app crashes.
  • Structured logging utility with log levels (debug, info, warn, error).
  • Sentry integration for real-time error tracking and performance monitoring.
  • Request ID correlation across frontend and Edge Functions.
  • Alerting rules for critical error spikes.
Section 02

Authentication & User Management

2.1 Sign-Up & Login
  • Email + password registration with server-side validation.
  • Magic link (passwordless) login via email.
  • Social OAuth: Google, Apple, GitHub (configurable per deployment).

  • Automatic token refresh — users never get logged out mid-session.
2.2 User Profiles
  • Profiles table linked to Supabase Auth with RLS.
  • Editable display name, avatar, phone, and preferred language.
  • Profile completion progress indicator.

2.3 Role-Based Access Control (RBAC)

  • JWT claims carry role information for client-side gating.
  • RLS policies enforce role checks on every database query.
  • Admin role grants access to the Admin Dashboard.
  • Dealer role grants access to order management and test-drive requests.
2.4 Account Settings
  • Password change with current-password verification.
  • Email change with re-verification flow.
  • Notification preferences (email, push, SMS toggles).

Section 03

The Digital Garage

3.1 Core Garage UI
  • Four-lane layout: Saved Builds, Purchases, Prototypes, Wishlist.
  • Each lane displays vehicle configuration cards with thumbnail, title, model, price summary, tags, and last-modified timestamp.
  • Real-time synchronization via Supabase Realtime — changes on one device appear instantly on all others.
  • Responsive grid that adapts from 4-column desktop to single-column mobile.
  • Loading skeletons, empty states, and error recovery for every lane.
3.2 Save to Garage
  • One-click save from any configurator view.
  • Full configuration JSON stored in garage_items.config_payload (JSONB).
  • Automatic initial version snapshot created on first save.
  • Auth-aware: redirects unauthenticated users to login, then returns them to the exact configurator state for seamless save completion.
  • Optimistic UI update with rollback on failure.
  • Success toast with link to open the saved item in the Garage.
3.3 Edit & Rename
  • Modal editor for title, description, and state.
  • Input validation: required title, max character limits.
  • Partial update support — only changed fields are sent to the server.
  • Automatic updated_at timestamp refresh.
  • Version snapshot created if the underlying configuration changes.
3.4 Version History & Diff View
  • Vertical timeline of every version ever saved for a garage item.
  • Each entry shows version number, date, and a human-readable diff summary.
  • Click any version to see the full configuration snapshot.
  • Visual diff: added options highlighted in green, removed in red, changed in amber, with price delta displayed for each change.
  • “Restore to this version” action: creates a new version from the restored state, preserving full history.
3.5 Sharing & Deep Links
  • Generate unique shareable URL for any garage item.
  • Share modal with: copy-to-clipboard button, QR code for mobile scanning, privacy controls, and optional link expiry.
  • Privacy levels: Public (anyone), Unlisted (link-only), Private (owner).
  • Access tracking: view count, last accessed timestamp.
  • Deep link handler renders a read-only view of the shared configuration with a “Save to my garage” call-to-action.
  • Supabase RPC functions: create_share_link, get_shared_item, update_share_settings — all secured with RLS.
3.6 State Transitions & Order Linking
  • State enum: saved, purchased, prototype, wishlist, archived.
  • Validated transitions (e.g., cannot move from archived to purchased).
  • Stripe webhook integration: on payment success, the linked garage item automatically transitions to “purchased” and a milestone is created.
  • On refund: state reverts to “saved” with a refund milestone logged.
  • Manual drag-and-drop between lanes with confirmation dialog.
  • Activity log entry created for every state change.
3.7 Tags & Goal Configuration
  • Chip-based multi-select tag system.
  • Predefined tags: track, grand-tourer, concept, daily-driver (extensible).
  • Tags displayed visually on each car card.
  • Tag filtering with AND/OR logic toggle.
  • Tag counts shown in filter bar.
  • Filter preferences persisted to localStorage.
3.8 Open in Configurator (Deep Link)
  • “Configure” button on every garage card.
  • Loads the saved configuration, extracts vehicle selection and all option mappings, and hydrates the configurator store so the user picks up exactly where they left off.
  • Graceful handling of missing options (e.g., discontinued color).
  • Loading state with branded animation during extraction.
3.9 Timeline & Milestones
  • Vertical timeline attached to each garage item.
  • Milestone types: created, updated, purchased, delivered, custom.
  • Expandable detail view per milestone.
  • Users can add custom milestones (e.g., “Showed dealer”, “Approved by spouse”).
  • Future-date placeholders for estimated delivery.
3.10 Advanced Filtering & Sorting
  • Filter by: state, date range, price range, vehicle model, tags.
  • Sort by: date (newest/oldest), price (high/low), name (A–Z).
  • Saved filter presets with quick-apply buttons.
  • “Clear all filters” one-click reset.
  • Client-side search by title and description for instant results.
  • Server-side filtering for date and price ranges for efficiency.
3.11 PDF Export
  • Edge Function generates a branded PDF specification sheet per garage item.
  • PDF contents: vehicle details, selected options with individual prices, pricing breakdown, high-res render image, QR code linking to the shared configuration, and branded header/footer with orange accents.
  • Asynchronous job queue: pdf_export_jobs table tracks status (queued, processing, completed, failed).
  • Generated PDFs stored in Supabase Storage with signed download URLs.
  • Typical generation time: 2–5 seconds.
3.12 Test Drive Scheduling
  • Scheduling modal pre-filled with the garage item’s model and the user’s contact info.
  • Date picker restricted to future dates.
  • Dynamic dealer selector supporting multiple dealership locations.
  • On submit: record created, email dispatched to the selected dealer and confirmation sent to the user via Edge Function.
  • Status tracking: pending → confirmed → completed / cancelled.
  • Dealers can update status via API; users see live status on their card.
  • All actions logged for audit trail.
Section 04

2D Visual Configurator Engine

4.1 Manifest-Driven Architecture
  • Every vehicle model defined by a JSON manifest stored in Supabase.
  • Layer stack with z-index ordering, dependency graphs between layers, and variant mapping from option values to asset URLs.
  • Manifest Editor UI for admin: drag-and-drop layer reordering, visual dependency graph, direct asset upload, JSON export/import, and validation before publish.
  • Versioned manifests with draft/published/archived lifecycle and one-click rollback.
4.2 Layered Image Composition
  • High-fidelity 2D rendering by stacking transparent PNG/WebP layers.
  • Each configurable option (paint, wheels, calipers, aero, interior trim) maps to a layer with its own z-index.
  • Option swap triggers only the affected layer reload — all other layers remain cached, achieving <100ms perceived swap time.
  • Multi-angle support: front ¾, side profile, rear ¾, and interior views, each with its own layer set.
4.3 Adaptive Image Quality Scaling
  • Automatic detection of viewport size, device pixel ratio (DPR), and network speed.
  • Quality tiers: Low (800px, 70%), Medium (1200px, 85%), High (2000px, 95%), Ultra (original, lossless).
  • Supabase Storage CDN image transformations for on-the-fly resizing.
  • Progressive loading: low-quality placeholder → full resolution swap.
  • IntersectionObserver-based lazy loading and swatch hover prefetch.
  • Performance budgets: LCP < 2.5s, image load < 1s on 3G, zero layout shift.
4.4 Compatibility Rules Engine
  • Rules stored in database with types: “requires” and “incompatible”.
  • Client-side evaluation engine re-evaluates all rules in <10ms on every option change.
  • Violation feedback: inline alerts with i18n messages, affected options highlighted, and auto-resolve suggestions.
  • Automatic reconciliation: “requires” rules auto-select the dependency; “incompatible” rules disable the conflicting option.
  • Admin rule management UI: list, create, edit, delete, bulk import/export, test against sample configurations.
4.5 Camera Angle Transitions
  • Smooth animated transitions between viewing angles.
  • Parallax depth effect: layers shift at different rates creating a subtle 3D illusion.
  • Configurable easing functions and durations via manifest metadata.
  • Respects prefers-reduced-motion for accessibility. 60fps target.
4.6 Preset Configurations
  • Curated starter configurations: Performance Pack, Winter Pack, Launch Edition, etc.
  • Preset gallery with thumbnails, names, descriptions, and “Start with this” button.
  • “Start from scratch” option always available.
  • Presets managed via Supabase table with admin CRUD interface.
4.7 Studio Lighting Filter
  • Background/lighting presets: Studio (neutral), Track (dynamic), Gallery (dramatic), Sunset (warm).
  • Segmented control with visual thumbnails and preloaded fade transitions.
  • User preference persisted per configuration.
4.8 Undo / Redo System
  • Full history stack: past[] / present / future[] with immutable snapshots.
  • Keyboard shortcuts: Ctrl+Z (undo), Ctrl+Y (redo).
  • History depth limit (50 states) to bound memory usage.
  • Optional localStorage persistence so history survives page reloads.
4.9 Compare Mode
  • Side-by-side comparison of two configurations.
  • Diff highlighting: added (green), removed (red), changed (amber).
  • Option-by-option and price-by-price comparison table.
  • Responsive: stacks vertically on mobile.
4.10 Variant Availability Alerts
  • Real-time stock tracking per option value per region via Supabase Realtime.
  • Low-stock warnings and out-of-stock indicators shown inline.
  • Unavailable options automatically disabled with explanation.
4.11 Wishlist Overlay
  • Floating “Add to Wishlist” button on the configurator page.
  • Auth-aware: redirects guests to login, returns to exact state.
  • Toast confirmation with link to Garage.
4.12 Watermark Rendering
  • Client-side canvas watermark overlay on renders. Configurable opacity and position.
  • Server-side watermarking pipeline for high-res exports.
4.13 Showcase Mode
  • Full-screen immersive presentation of the configured vehicle.
  • Environment presets: winter, summer, studio, track, gallery.
  • Text/copy overlays for marketing presentations.
  • Shareable showcase URLs. Deep link back to configurator for editing.
4.14 AR Preview Integration
  • Device capability detection: WebXR, ARKit (iOS), ARCore (Android).
  • AR asset URLs in manifest: USDZ (iOS) and GLB (Android/Web).
  • Launches native AR viewer or WebXR session. Graceful fallback on unsupported devices.
Section 05

3D Immersive Configurator Engine

5.1 React Three Fiber Scene
  • Full WebGL scene built with React Three Fiber + Drei.
  • Perspective camera with configurable FOV and position presets.
  • Orbit controls: rotate, pan, zoom with damping.
  • HDRI environment lighting + directional sun light. Ground plane with shadow receiver.
  • frameloop=“demand” for battery-efficient rendering — only re-renders when the scene changes.
5.2 GLB Streaming & Caching
  • Asset pipeline: source GLB → Draco compression → KTX2 texture conversion → geometry optimization → LOD variant generation → Supabase Storage.
  • DRACOLoader and KTX2Loader integration for maximum compression.
  • Progressive loading with placeholder meshes during download.
  • IndexedDB caching of decoded geometry buffers — repeat visits load from local cache with zero network requests.
  • Versioned assets with automatic cache invalidation. Retry logic with exponential backoff.
5.3 Level of Detail (LOD)
  • Automatic device capability detection (GPU tier, available memory).
  • Camera-distance-based LOD switching. Three tiers: high, medium, low.
  • Automatic fallback to 2D configurator on low-end devices.
5.4 Interior / Exterior Toggle
  • GLB node partitioning: interior group, exterior group, shared nodes.
  • Smooth camera transitions between exterior wide-angle and interior close-up.
  • Light rig swap: exterior uses HDRI + sun; interior uses ambient + accent.
5.5 Paint Shader System
  • Custom MeshPhysicalMaterial-based paint shader with physical parameters: base color, metallic, roughness.
  • Metallic flake layer: configurable density, size, and color.
  • Clearcoat layer: adjustable strength and roughness.
  • Control panel with sliders, color pickers, and preset paint materials.
5.6 Studio Light Presets (3D)
  • Preset picker with thumbnail grid and hover preview.
  • Smooth HDRI crossfade transitions. User preference persisted per configuration.
5.7 Animated Parts System
  • GLTF animation tracks for doors, trunk/frunk, spoiler, and aero elements.
  • Visual timeline scrubber with play/pause, speed control, and loop.
  • useAnimationController hook for programmatic playback.
5.8 Volumetric Lighting & Fog
  • Quality tiers: off (low-end), basic fog (medium), full volumetric (high).
  • Automatic quality selection based on GPU tier with user override.
5.9 Background Stage Configuration
  • HDRI environment selector with rotation and blur sliders.
  • Prefiltered PMREM generation for accurate reflections.
  • Preferences persisted per user profile and per configuration.
5.10 WebXR / VR Integration
  • WebXR API capability detection with onboarding prompt.
  • Immersive VR sessions with teleport controls and safe play-area boundaries.
  • Hand tracking support (device-dependent). Graceful session management.
5.11 High-Res Render Export
  • Multi-pass supersampled capture pipeline. Resolution presets: 1080p, 4K, 8K.
  • Format options: PNG, JPEG, WebP. Optional watermark overlay.
  • Edge Function for server-side ultra-high-res rendering. Job queue with status tracking.
5.12 Sound Design Integration
  • Interaction-to-audio mapping: option click, camera whoosh, door latch, engine rev.
  • Spatial 3D audio via Web Audio API. Debounced playback. Global mute toggle.

6.2 Pricing Panel UI

  • Webhook handler: payment success → order “paid”, garage item → “purchased”, milestone created, confirmation email sent.

  • Idempotency keys. Comprehensive error handling and retry logic.
6.4 Order Management
  • Order lifecycle: pending → paid → processing → completed / cancelled / refunded.
  • Line-item detail. User-facing order history with status badges.
  • Admin-facing order management console. Email notifications at each status transition.
6.5 Inventory Intelligence
  • Real-time stock tracking per option per region.

Section 11

Performance & Optimization

11.1 Code Splitting & Lazy Loading
  • Route-level code splitting: each page is a separate chunk.
  • Dynamic imports for heavy modules (3D engine, PDF library, AI chat).
  • Prefetching of likely-next routes on hover. Tree-shaking for minimal bundle.
11.2 Rendering Optimization
  • Fine-grained Zustand subscriptions. React.memo and useMemo for expensive computations.
  • Virtual scrolling for long lists. requestAnimationFrame for 60fps animations.
11.3 Network & Asset Optimization
  • Optimistic updates. Debounced API calls. Batched Supabase queries.
  • WebP/AVIF images. Draco-compressed GLB (up to 90% reduction). KTX2 textures.
  • Hashed filenames for aggressive browser caching.
Section 12

Security & Compliance

12.1 Data Protection
  • Row-Level Security on every table — enforced at database level.
  • Service role keys used only in Edge Functions, never exposed to client.
  • Input validation on all endpoints. SQL injection prevention. XSS prevention via React escaping.
12.2 Authentication Security
  • JWT tokens with short expiry and automatic refresh. Secure cookie storage.
  • Rate limiting on auth endpoints. CAPTCHA readiness for abuse prevention.
12.3 Infrastructure Security
  • HTTPS everywhere. Security headers: CSP, HSTS, X-Frame-Options.
  • No source maps in production. Obfuscated chunk filenames.
  • Dependabot for automated dependency vulnerability scanning.
12.4 Compliance
  • GDPR-ready: account deletion, data export, consent management.
  • WCAG 2.1 AA accessibility target. Cookie consent readiness.
  • Audit logging for all admin and financial actions.
