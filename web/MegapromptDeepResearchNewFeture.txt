PART 3: THE PUBLISHING ARCHITECTURE (RAW CONTEXT)
--------------------------------------------------------------------------------
This is how we currently publish sites. Inside `publish.js`:
1. We run a build inside the E2B Sandbox (`verify-sandbox-build.js`).
2. We `tar` the `dist/` folder and `base64` it out of the container to our backend.
3. We unpack the tarball into memory.
4. We upload the built static files (`index.html`, `assets/index.js`, etc.) into a Supabase Storage Bucket called `published-sites/${slug}/`.
5. We rewrite the `index.html` on the fly to inject the metadata and the Volturiano brand stamp.

When a user visits `volturiano.com/sites/MyAwesomeSite`, our Express server intercepts the API request and proxies the fetch directly to Supabase storage to return `published-sites/MyAwesomeSite/index.html`.

PART 4: THE MULTI-PAGE VISION & PROBLEM STATEMENT
--------------------------------------------------------------------------------
We want to transition this pipeline into an emergent Multi-Page Application (MPA) Builder.

If a user attaches a "Premium Login Component" and says "Add a login system and an About Us page", the system should:
1. Understand it needs to create routing dynamically.
2. Install `react-router-dom` (or a similar lightweight standard, if not pre-installed).
3. Transform the current `App.jsx` from a stacked landing page into a Layout/Routing shell (`<BrowserRouter>`, `<Routes>`, `<Route>`).
4. Abstract the home page into `src/pages/Home.jsx`.
5. Create `src/pages/About.jsx` and `src/pages/Login.jsx`, utilizing the community component the user provided.
6. Automatically wire up the main Navbar so that the `<Link>` tags correctly point to `/about` and `/login`.

Furthermore, when the site is published and hosted at `volturiano.com/sites/Sitename`, navigating to `volturiano.com/sites/Sitename/about` must not result in a 404 from our reverse proxy. It must correctly load the React Router state and display the About page, maintaining the base path dynamically without relying on brittle backend configurations.
