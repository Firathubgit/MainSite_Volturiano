VOLTURIANO SuperSystem Blueprint (Everything)

Version: initial
Scope: This single file captures the persistent intent, rationale, and operating
principles for the entire VOLTURIANO Website + Configurator program. It
consolidates architecture, conventions, security, performance strategies,
workflows, schemas, asset contracts, extensibility, how‑to guides, and roadmap
into one human‑readable source of truth for future engineers and stakeholders.

--------------------------------------------------------------------
1) Mission & Non‑Negotiables
--------------------------------------------------------------------
- Build a premium, investor‑grade, future‑proof website and configurator that
  feels like a digital atelier: “commission, not purchase”.
- Stack: React + Vite (JS), React Three Fiber + Drei (optional 3D), CSS Modules,
  i18next, Zustand, Framer Motion. Backend: Supabase (Postgres, Auth, Storage,
  Edge Functions) and Stripe via Edge Functions only.
- Dual visualization engine: 2D layered images (primary realism + reach) and
  optional real‑time 3D (immersive mode, AR/VR readiness).
- Data‑driven everything: manifests for assets, SQL for compatibility rules,
  i18n JSON for copy, flagged features for progressive rollout.
- Performance and reliability first: instant UI feedback, lazy loading,
  demand‑driven 3D rendering, CDN delivery, RLS security, idempotent webhooks.

Why this stack
- React/Vite = ergonomics + fast HMR + small production bundles.
- R3F lets us keep 3D within the React mental model and Suspense.
- Supabase consolidates DB/Auth/Storage/Edge in one place with RLS.
- Stripe Checkout/Webhooks move PCI scope to Stripe and simplify payments.
- CSS Modules keep CSS simple and scoped; design tokens via CSS variables enable
  Base/Sport/Luxury themes without a framework dependency.

3) Frontend Architecture & Conventions
--------------------------------------------------------------------
App shell
- React Router + Suspense boundaries; providers for i18n and stores; global
  error boundary with branded fallback.

State management
- Zustand for minimal boilerplate and fine‑grained subscriptions. Stores:
  - configStore: selected vehicle/options, derived price, config code.
  - userStore: auth session, saved configs list.
  - uiStore: viewer mode, environment, audio mute, prefers‑reduced‑motion.

Visualization engines
- 2D layered images (primary):
  - Transparent per‑part layers (body, wheels, calipers, etc.) for each angle.
  - Manifests map (model, angle, option variant) => asset URL.
  - Hover prefetch for color swatches; fade transitions; instant swaps.
  - Universal device support and photorealism.

- 3D (optional) with R3F:
  - GLB with Draco meshes and KTX2 textures, HDRI IBL, soft/contact shadows.
  - frameloop="demand" to render only on change; LOD via drei <Detailed>.
  - Car‑paint material via MeshPhysicalMaterial or custom shader as needed.
  - Used for “cinematic” moments, interior, close‑ups, and future AR/VR.

Styling
- CSS Modules + PostCSS; global tokens in :root (colors, spacing, motion,
  shadows, z‑layers). Themes: base/sport/luxury via [data-theme] overrides.
- Accessibility: semantic HTML, focus‑visible, ARIA patterns, prefers‑reduced‑
  motion respected; alt text from i18n.

Animation & Audio
- Framer Motion for UI; optional GSAP for scroll scenes; use transform/opacity.
- Subtle UI sounds; always gated by user interaction + mute toggle.

Internationalization
- i18next + react‑i18next; namespaces per feature (common, nav, models,
  configurator, account, world, investor). All copy in JSON, never hardcoded.

Coding conventions
- Functional components, hooks; small composable pieces; JSDoc for shared
  helpers; kebab-case files; PascalCase components; use‑ prefix for hooks.

4) Backend (Supabase) Architecture
--------------------------------------------------------------------
Core tables
- vehicles(id, name, base_price, description, performance_specs jsonb,
  segment, drivetrain, subbrand)
- option_groups(id, name, display_order)
- options(id, group_id -> option_groups, name, ui_control_type)
- option_values(id, option_id -> options, name, price_delta, image_url,
  material_id)
- materials(id, name, properties jsonb)
- compatibility_rules(id, rule_type enum('requires','incompatible'),
  primary_option_value_id, secondary_option_value_id)
- user_configurations(id, user_id, vehicle_id, name, selected_options jsonb,
  config_code unique)
- orders(id, user_id, configuration_id, status, stripe_session_id)

Why JSONB for selected_options
- Flexibility as option sets evolve; relational tables handle constraints,
  while JSONB stores the chosen mapping option_id => option_value_id compactly.

Security
- RLS enabled by default. user_configurations accessible only to owner.
- Admin: role claim grants elevated RPC/Edge access; UI guarded.
- Public buckets: read‑only assets. Private: signed URLs with short TTL.

Edge Functions (server‑only logic)
- create-checkout-session: compute price server‑side from DB, create Stripe
  session, return id. Uses service keys; never expose to client.
- stripe-webhook: verify signature, record order, mark configuration as paid;
  idempotent and auditable logs.

Environments & migrations
- Local via Supabase CLI; staging and production projects. Declarative SQL
  migrations under /supabase/migrations. CI deploys develop -> staging, main ->
  production.

6) Performance Doctrine
--------------------------------------------------------------------
- Perceived speed wins: instant feedback, optimistic UI, hover prefetch.
- Code split by route and heavy features; lazy‑load viewer; demand frameloop.
- Budgets: small initial JS (<~200kb gzip target for shell), fast LCP (<2.5s on
  mid‑tier device), stable CLS, smooth viewer FPS.
- Autoscale quality: reduce 3D quality on low‑end devices; always offer 2D.


--------------------------------------------------------------------
7) Security & Privacy Baseline
--------------------------------------------------------------------
- Secrets are never committed. Client uses only anon key. Service role and
  Stripe secrets live in Edge environment.
- RLS everywhere; policies precede exposure. CSP, Referrer‑Policy,
  Permissions‑Policy, HSTS in production. Input sanitization on any custom
  endpoints.

13) Compatibility Rules (SQL)
--------------------------------------------------------------------
Table
- compatibility_rules(id, rule_type enum('requires','incompatible'),
  primary_option_value_id, secondary_option_value_id)

Semantics
- requires: choosing primary implies secondary must be active (auto‑select or
  enable‑only with message).
- incompatible: choosing primary disables secondary; UI shows reason.

UI contract
- On selection change, fetch rules for the affected value ids and update the UI
  availability; messages stored in i18n (e.g., configurator.rules.* keys).

16) How‑To Quick Guides
--------------------------------------------------------------------
Add a vehicle
1) DB: insert vehicles; create option_groups/options; add option_values; define
   compatibility_rules.
2) Assets: upload 2D layers (+ optional GLB); update manifest JSON; commit.
3) i18n: add model/option labels + rule reasons.
4) App: add to models carousel; enable flags if soft‑launch.
5) QA: 2D angles ok, instant swaps, price sums, rules behave, config save/load.

Add an option/variant
1) DB: insert option_values (+ rules if needed).
2) Assets: upload new layers for all angles; update manifest; 3D materials.
3) i18n: labels + rule texts. 4) Verify visual swap, price, rules.

Upload assets
- Hash filenames; upload to images/models/hdri buckets; set permissions; update
  manifest with exact URLs and commit.

Enable 3D for a model
- Set VITE_ENABLE_R3F_MODE=true; upload GLB + KTX2; update manifest 3D section;
  add HDRIs; test FPS and parity with 2D.

Add a language
- Create /web/src/i18n/<locale> with core namespaces; register in init and
  switcher; screenshot key flows for PR.

21) Start Animation (Intro) System
--------------------------------------------------------------------
Purpose
- A cinematic intro shown only on the first visit to the Home route per browser
  session. It introduces VOLTURIANO’s visual language with a fast image shuffle,
  a brief “enlarge” emphasis, a stacked cone reveal, then a compact spread and
  a top-to-bottom fade-out before handing control to the site.

Files
- web/src/pages/Start/IndexGate.jsx        (gates whether to show the intro)
- web/src/pages/Start/StartAnim.jsx        (animation logic + timeline)
- web/src/pages/Start/StartAnim.module.css (scoped styles)

Routing & Gating
- The app shell (web/src/app/App.jsx) routes "/" to IndexGate.
- IndexGate checks sessionStorage.startPlayed:
  - If missing: navigate to "/start" (StartAnim).
  - If present: render Home directly.
- StartAnim sets sessionStorage.startPlayed = "1" on completion, then navigates
  back to "/". Subpages (e.g., /models, /configurator) never invoke the intro.

Asset Loading (Vite glob)
- StartAnim auto-loads local images from "web/src/assets/start/*.{png,jpg,jpeg,webp,avif}"
  using import.meta.glob({ eager: true, as: 'url' }). Filenames are sorted to
  stabilize order. If the folder is empty, Unsplash placeholders are used.
- Six images are used; if more exist, the first 6 are taken.

Color & Theme
- Dark palette:
  - #111111 Night
  - #1F1F1F Eerie Black
  - #303030 Jet
  - #3A3A3A Jet
  - #E10600 Chili Red
  - #FF4520 Coquelicot
- CSS is modular and localized under StartAnim.module.css; global tokens are in
  web/src/styles/variables.css.

Timeline (Framer Motion)
- Constants (StartAnim.jsx):
  - SHUFFLE_MS = 200 (5 Hz shuffle)
  - MOVE_DURATION = 0.5s (bottom-center -> center)
  - SHUFFLE_TOTAL_MS = 3000 (total shuffle time)
  - ENLARGE_MS = 450ms (pop emphasis between shuffle and stack)
  - TOP_STACK_SCALE = 1.35 (keep top card enlarged in stack/spread)
  - FADE_ITEM_DELAY = 0.05s (cascade)
  - FADE_ITEM_DURATION = 0.15s
  - SPREAD_OFFSET = 30px (overall Y offset for spread)
  - ENLARGE_Y = -6px (stabilized Y so no “tick” when transitioning)
- Phases:
  1) move: single card rises from bottom center to center (0.5s).
  2) shuffle: single card shuffles image content at 5 Hz (to 3.0s total).
  3) enlarge: card scales to 1.35x for 450ms; Y remains ENLARGE_Y to avoid drift.
  4) stack: morph into a stacked cone (top card keeps 1.35x instantly).
  5) spread: vertical spacing expands slightly (size-aware, compact overall).
  6) hold: brief dwell, then
  7) fade: cards fade top-to-bottom (staggered), then overlay fades and route
     navigates back to "/".
- The timeline is implemented with a few setTimeout checkpoints; all clean up on
  unmount. Shuffle uses setInterval, cleared at the correct boundary.

Stack Geometry & Spacing
- Six items with per-depth max scale:
  MAX_SCALES = [1, 0.85, 0.7, 0.55, 0.4, 0.25]
- During “stack” the top element remains enlarged (TOP_STACK_SCALE) to match the
  preceding “enlarge” phase (no shrink/flicker).
- Stacked vertical offsets are accumulated and size-aware (tighter as items get
  smaller). Spread spacing also scales with size and depth and is tuned to keep
  the group compact and near center.

Side Text Ornaments (no gradients)
- Minimal copy lines are displayed on left/right during the intro:
  LEFT:  "VISION BUILT"
  RIGHT: "MODERN SPEED"
- These gently animate opacity/position across phases and fully fade during the
  final cascade.

Implementation Notes
- The stage is sized to 70vh and centers content with a transparent background.
- Card sizes are 140x140px (scaled per phase). The module CSS avoids any box
  shadow or “plates” behind the cards to keep the scene clean and dark.
- Accessibility: images include alt="intro"; prefers-reduced-motion can be used
  in the future to skip animations and directly continue to Home.

Operational Tips
- To preview the intro again: remove sessionStorage.startPlayed in DevTools or
  open a new window/private tab; or navigate directly to "/start".
- To change the side text, update the two strings in StartAnim.jsx (labels only).
- To supply brand images, drop exactly 5–6 files into web/src/assets/start/.
