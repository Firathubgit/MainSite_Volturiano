### MEGA-PROMPT 1: CORE DATABASE SCHEMA & LIFECYCLE ✅
**Goal:** Establish the fundamental data structures for community submissions, job processing, and component extension.

**Context:**
- Project at: `c:\Users\Firat\Documents\Projects\MainSite_Volturiano`
- Database: Supabase (PostgreSQL)
- Key Spec: S9.2 (State Machine), S9.7 (Database Schema), S9.11 (Ratings), S9.14 (Feedback Loop).

**Task:**
Create the database migration file `web/server/migrations/008_phase_s9_community_core.sql` containing:
1. **`community_submissions` Table**: Include columns for `user_id`, `submission_type` (component/template), `name`, `code` (original/cleaned), `content_hash` (SHA-256), `quality_score`, `status` (with CHECK constraint for: draft, processing, pending_review, approved, rejected, flagged, active, deprecated, archived), and processing timestamps.
2. **`submission_jobs` Table**: Async queue for LLM analysis with `status` (pending, running, completed, failed), `attempts`, `max_attempts`, and `retry_after`.
3. **`llm_cost_log` Table**: Columns for `operation`, `model`, `estimated_cost_usd`, and `tokens_used`. Add a helper function `get_daily_llm_cost()`.
4. **`ai_selection_events` Table**: For the feedback loop (build_id, component_id, was_selected, was_kept).
5. **`component_ratings` Table**: User reviews (1-5), review text, and a unique constraint on `(component_id, user_id)`.
6. **Existing `components` Table Alterations**: Add `preview_video_url`, `submission_id`, `content_hash`, `version_number` (default 1), and `parent_component_id` (for versioning).
7. **Indexes**: Create indexes for author, status, content_hash, and creation dates.
