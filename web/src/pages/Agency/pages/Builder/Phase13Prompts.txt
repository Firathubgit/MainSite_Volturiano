██  MEGA-PROMPT 1 of 3: The Persistence Engine (Backend & Auto-Save)
================================================================================

CONTEXT:
We have the basic database schema (projects, snapshots, profiles). Now we need to bridge 
the gap so that every build in the Generation.jsx is automatically saved and can be 
listed in a dashboard. The user should never lose work if they close the tab.

FILES TO MODIFY/CREATE:
- web/server/routes/dashboard.js (New)
- web/server/index.js (Register new routes)
- web/src/pages/Agency/pages/Builder/Generation/Generation.jsx (Auto-save injection)

TASK:
1. BACKEND: Create the Dashboard API (`web/server/routes/dashboard.js`):
   - Implement `GET /api/dashboard/projects`: Fetch all projects for the authenticated user, 
     ordered by `updated_at` DESC.
   - Implement `GET /api/dashboard/stats`: Return a summary object (Total Projects, Total 
     Credits, Total Published Sites).
   - Implement `DELETE /api/dashboard/projects/:id`: Securely delete a project if owned by user.
   - Update `web/server/index.js` to handle these routes with `requireAuth`.

2. FRONTEND: "The Persistence Hook":
   - Update `Generation.jsx` to perform "Incremental Saves".
   - Trigger a `fetch('/api/projects/update', ...)` call after ANY major state change:
     • After a new file is written.
     • After a chat message is added.
     • When the design system or component plan is finalized.
   - Ensure `generated_files` and `chatMessages` are stored in the `projects` table.

3. SNAPSHOT LOGIC:
   - Implement a "Manual Snapshot" button in the builder UI that hits `/api/snapshots`.
   - This allows users to create "Version 1.0", "Version 2.0" etc.

GOAL:
After this prompt, the database will be a living reflection of the user's progress in the 
builder, and we will have the JSON endpoints needed to build the UI.
