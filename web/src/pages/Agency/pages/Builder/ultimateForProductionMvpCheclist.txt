## Executive Summary

The MVP development phase is nearing completion. This document serves as the absolute source of truth for all tasks required to transition Volturiano Builder from a local development environment into a highly available, robust production environment. 

It covers everything from locking down database security, verifying Stripe webhooks in live mode, migrating environment variables, and conducting final QA, to actual launch day operations and post-launch monitoring.

---

## Section P1: Pre-Launch — Infrastructure & Security Finalization

**Status:** PENDING
**Priority:** CRITICAL

### P1.1 Supabase Database Lockdown
- [ ] **Disable Public Access:** Ensure the database is not publicly accessible without authentication.
- [ ] **RLS Policy Audit:** Double-check every single Table (profiles, projects, published_sites, community_submissions, etc.) to ensure Row Level Security (RLS) is strictly enforced. No bypasses allowed.
- [ ] **Security Definer Functions:** Audit all PostgreSQL functions (e.g., `handle_new_user`, `deduct_credits_safe`) to ensure they handle edge cases and cannot be exploited via SQL injection.
- [ ] **Point-in-Time Recovery (PITR):** Enable automated daily backups and PITR in the Supabase production environment.

### P1.2 Supabase Storage Configuration
- [ ] **Storage Buckets RLS:** Ensure storage buckets (`component-previews`, `user-avatars`, etc.) have correct RLS policies (e.g., public read, authenticated insert/update for own files).
- [ ] **File Size & Type Limits:** Enforce strict file size limits (e.g., 5MB max for avatars) and allowed MIME types in Supabase Storage to prevent abuse.

### P1.3 Rate Limiting & Abuse Prevention
- [ ] **API Rate Limiting:** Implement robust rate limiting on all Express backend routes (especially AI generation endpoints like `/api/apply-ai-code-stream` and `/api/publish-site`) to prevent DDoS attacks and API bankrupting.
- [ ] **E2B Sandbox Limits:** Verify execution timeouts and memory limits are correctly configured for the Firecracker MicroVMs to contain runaway generations.

## Section P2: Pre-Launch — Stripe & Monetization Verification

**Status:** PENDING
**Priority:** CRITICAL

### P2.1 Transition to Stripe Live Mode
- [ ] **Create Live Products:** Re-create all 3 subscription plans (Starter, Pro, Studio) and 3 one-time credit packs in the Stripe Production Dashboard. (Use the Stripe "Copy to Live Mode" feature to automate this if possible).
- [ ] **Update Live Price IDs:** Swap out all Test Mode Price IDs in the production `.env` file with the new Live Mode Price IDs.

### P2.2 Stripe Webhook Live Configuration
- [ ] **Live Webhook Endpoint:** Register the production webhook URL (e.g., `https://api.volturiano.com/webhooks/stripe`) in the Stripe Live Dashboard.
- [ ] **Live Webhook Secret:** Add the Live `STRIPE_WEBHOOK_SECRET` to the production environment variables.
- [ ] **Listen for Events:** Ensure the webhook listens to `checkout.session.completed`, `invoice.payment_succeeded`, `invoice.payment_failed`, `customer.subscription.updated`, and `customer.subscription.deleted`.

### P2.3 Real-World Payment Testing
- [ ] **Test Live API Keys:** Perform a real checkout using a live credit card (can immediately refund it) to ensure the end-to-end flow creates the checkout session, processes the payment, fires the webhook, and provisions the credits in Supabase.
- [ ] **Test Customer Portal:** Verify users can successfully access the Stripe Customer Portal, upgrade/downgrade plans, and cancel subscriptions via the Live Dashboard.

## Section P3: Pre-Launch — QA & Edge Case Testing

**Status:** PENDING
**Priority:** HIGH

### P3.1 Credit System Edge Cases
- [ ] **Zero Credits Behavior:** Verify the UI gracefully locks out AI generation when a user has 0 total available credits or prompts for an upgrade.
- [ ] **Insufficient Credits Mid-Build:** What happens if a build costs more credits than the user currently holds? Ensure the system calculates costs beforehand or fails gracefully without breaking the AI state.
- [ ] **Credit Deduction Accuracy:** Perform multiple generations and mathematically verify that credits are deducted precisely according to the Multi-Bucket hierarchy (Monthly Free -> Signup Bonus -> Subscription -> Purchased).

### P3.2 Cross-Browser & Device Testing
- [ ] **Browser Compatibility:** Test the Builder UI thoroughly on Chrome, Safari, Firefox, and Edge. Pay special attention to the drag-and-drop mechanics, Framer Motion animations, and the AI streaming window.
- [ ] **Responsive Design:** Verify the CreditLimitModal, BuilderNavBar, and Dashboard panels render correctly on mobile and tablet breakpoints. (Note: Builder itself might be desktop-only, but billing/dashboard should be responsive).

### P3.3 AI Generation Stress Testing
- [ ] **Concurrent Builds:** Test the backend by initiating multiple heavy AI build requests simultaneously to ensure the Express server and E2B sandbox instances scale without bottlenecking.
- [ ] **Error Handling:** Intentionally trigger API failures (e.g., invalid prompt, context length exceeded) and verify the frontend displays a user-friendly error message rather than crashing.

## Section P4: Pre-Launch — Environment & Deployment

**Status:** PENDING
**Priority:** CRITICAL

### P4.1 Environment Variable Audit
- [ ] **Frontend Env Vars:** Verify all `VITE_` variables (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_STRIPE_PUBLIC_KEY`, etc.) are correctly set in the production deployment pipeline (e.g., Vercel/Netlify).
- [ ] **Backend Env Vars:** Verify all secrets (`SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `OPENAI_API_KEY`, `E2B_API_KEY`, etc.) are securely stored in the production backend hosting provider (e.g., Railway, Render, AWS).

### P4.2 Production Builds
- [ ] **Frontend Build Optimization:** Run `npm run build` locally and ensure there are no missing dependencies, massive bundles, or unresolved imports.
- [ ] **Backend Deployment:** Deploy the Express server and ensure it is accessible. Update the Frontend to point to the correct production API URL.

### P4.3 Custom Domain & SSL
- [ ] **DNS Configuration:** Ensure the main domain (`volturiano.com`) and API subdomains (`api.volturiano.com` or `builder.volturiano.com`) point correctly to the respective hosting providers.
- [ ] **SSL Certificates:** Verify SSL is successfully provisioned and enforced across all endpoints.

**Status:** PENDING
