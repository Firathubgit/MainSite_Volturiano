[DEEP DIVE: THE ARCHITECTURE OF HALLUCINATION MITIGATION]
The core challenge in our AI generation pipeline is "Best Practice Drift." Models like GPT-5.2 and GPT-4o are trained on modern web development patterns. In a standard project, using `react-intersection-observer` or `@headlessui/react` is the "correct" way to build. However, in our optimized sandbox environment, these dependencies are not pre-installed to keep build times low and complexity manageable.

Phase-by-Phase Hardening History:
- Phase 1 (Path Flattening): AI used to try and organize components into folders like `src/components/ui/Button.jsx`. This caused import failures because the build system expects everything in `src/components/`. We strictly enforced FLAT STRUCTURE.
- Phase 2 (Extension Enforcement): AI would occasionally omit `.jsx` in imports or use `.js` incorrectly. We mandated `.jsx` everywhere.
- Phase 3 (Utility Blacklist): AI assumed it could import a `cn()` helper from a local file. We forced it to implement `cn()` inline.
- Phase 4 (Icon Hardening): AI hallucinated `react-icons/lucide` (which doesn't exist) or used wrong names like `SearchIcon`. We blacklisted the path and enforced prefixes.
- Phase 5 (Export Standardization): AI used named exports, while `App.jsx` expected default exports. We mandated `export default`.
- Phase 6 (Syntax Hardening): AI used illegal backslashes in Tailwind brackets. We strictly forbade them.
- Phase 7 (Sidecar Hardening): AI assumed shared components like `./Modal` existed. We forced self-contained components.
- Phase 8 (Lucide Hardening): AI hallucinated `Paw` for `PawPrint`. we added a common pitfalls list.
- Phase 9 (External Library Block): AI used `@headlessui/react`. We blacklisted it and mandated Vanilla React state.
- Phase 10 (Utility Hook Block): AI used `react-intersection-observer`. We have now added this to the strict blacklist and commanded the use of Native APIs or allowed libs like `framer-motion`.

The "Vanilla Mandate" is our most successful measure. By forcing the AI to build EVERYTHING (toggles, accordions, scroll observers) using primitive React hooks (`useState`, `useEffect`) and Tailwind classes, we eliminate nearly all dependency errors.

[PHASE 11: DEFINITIVE FIX — WHITELIST-ONLY IMPORT ARCHITECTURE]
After 10 phases of prompt-level blacklisting (which kept failing because the AI can always
hallucinate a NEW library not on the blacklist), we implemented the ULTIMATE solution:
a CODE-LEVEL WHITELIST in `apply-ai-code-stream.js`.

WHY BLACKLISTING FAILED:
Blacklisting is a game of whack-a-mole. Each time we blocked one library
(@headlessui, react-intersection-observer), the AI would use another one
(@dnd-kit, use-gesture, lodash, etc.). The model is trained on millions of
projects that use these libraries, so it naturally reaches for them.

THE WHITELIST SOLUTION:
Instead of saying "don't use X", we now say "you may ONLY use these packages":
  - react, react-dom (core)
  - framer-motion (animations)
  - lucide-react (icons)
  - react-router-dom (routing)
  - react-icons (icon packs)
  - clsx, tailwind-merge (class utilities)

HOW IT WORKS (3-layer defense):
Layer 1 — sanitizeImports(code):
  Before ANY file is written to the sandbox, every import line is checked
  against the ALLOWED_PACKAGES set. If the import source is not whitelisted,
  the entire import line is COMMENTED OUT with a warning:
    // [STRIPPED] Illegal import removed: react-intersection-observer
  This means the component still renders (gracefully degraded) instead of
  crashing the ENTIRE site with a Vite import error.

Layer 2 — Package Install Filter:
  The extractPackages() function detects all npm packages mentioned in the
  generated code. Before Phase 11, ALL detected packages were auto-installed.
  Now, detected packages are filtered through isAllowedPackage() — only
  whitelisted packages are installed. Illegal packages are logged:
    [apply] BLOCKED illegal packages: react-intersection-observer

Layer 3 — Prompt Rules (retained from Phases 1-10):
  The system prompts in generate-single-component.js and plan-website-components.js
  still contain the blacklist rules. These serve as a "first line of defense" that
  REDUCES the frequency of hallucinations. But if the AI slips through, Layers 1-2
  catch it programmatically.
