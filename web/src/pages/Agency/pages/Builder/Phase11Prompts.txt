TASK:
Add 5 new API endpoints to web/server/routes/community/index.js. Place them ABOVE the
"export default router;" line at the bottom of the file. These are all PUBLIC endpoints
(no auth required) for the marketplace browse experience:

1. GET /api/community/browse
   Query params: type (component|template), category, subcategory, sort (popular|newest|quality|most_used),
   industry, color (light|dark|mixed|adaptive), style, page (default 1), limit (default 20), search (text)
   
   Logic:
   - If type === 'component': query `components` table WHERE status = 'active'
   - If type === 'template': query `templates` table WHERE status = 'active'
   - Apply category, subcategory, industry, color filters as .eq() or .contains() where applicable
   - If `search` param exists, use .textSearch('search_vector', search, { type: 'websearch' })
   - Sort mapping: popular = usage_count desc, newest = created_at desc, quality = quality_score desc, most_used = usage_count desc
   - Paginate with .range(offset, offset + limit - 1) and { count: 'exact' }
   - For components: also join author profile: select components.*, profiles!components_author_id_fkey(id, username, display_name, avatar_url, reputation_score)
   - For templates: same author join + also return a count of template_sections for each template
   - Response shape: { success: true, items: [...], total, page, pages, facets: {} }
   - For facets: run a separate aggregation query to get distinct categories with counts (for the sidebar)

2. GET /api/community/browse/trending
   Logic:
   - Fetch top 5 components by usage_count WHERE status = 'active', ordered desc, with author profile join
   - Fetch top 5 templates by usage_count WHERE status = 'active', ordered desc, with author profile join
   - Response: { success: true, components: [...], templates: [...] }

3. GET /api/community/components/:id
   Logic:
   - Fetch single component by id WHERE status = 'active'
   - Join author profile (username, display_name, avatar_url, reputation_score)
   - Fetch rating stats from component_ratings: count, average
   - Fetch related templates: query template_sections WHERE component_id = :id, join templates
   - Response: { success: true, component, author, ratings: { average, count }, relatedTemplates }

4. GET /api/community/templates/:id
   Logic:
   - Fetch single template by id WHERE status = 'active'
   - Join author profile
   - Fetch sections: query template_sections WHERE template_id = :id, ORDER BY section_order ASC
   - For each section, join to components table to get component name, thumbnail_url, category, quality_score
   - Response: { success: true, template, author, sections: [...], ratings: { average, count } }

5. GET /api/community/categories
   Logic:
   - Query distinct category + count from components WHERE status = 'active', GROUP BY category
   - Also query distinct subcategory per category
   - Response: { success: true, categories: [{ slug, name, count, subcategories: [...] }] }
