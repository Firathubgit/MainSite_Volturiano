1. EXECUTIVE SUMMARY & PRODUCT OVERVIEW
================================================================================

WHAT IS VOLTURIANO?
-------------------
Volturiano is a luxury sports automotive platform that combines cutting-edge
3D visualization technology with comprehensive vehicle configuration capabilities.
The platform enables users to customize luxury vehicles (specifically the Tornado
GT model) through an immersive web-based configurator, save configurations to a
personal garage, manage orders, and interact with an AI-powered assistant.

PRODUCT VISION
--------------
Volturiano aims to revolutionize the luxury car buying experience by providing:
- Real-time 3D visualization of vehicle customizations
- Seamless configuration management and comparison
- AI-powered assistance for configuration decisions
- Comprehensive admin tools for content and user management
- Multi-language support (English, Swedish)
- Mobile-responsive design with offline capabilities

TARGET AUDIENCE
---------------
- Primary: Luxury car enthusiasts and potential buyers
- Secondary: Dealers and sales representatives
- Tertiary: Internal content administrators and support staff

KEY DIFFERENTIATORS
-------------------
1. Dual Visualization Engine: Both 2D pre-rendered and 3D real-time rendering
2. Advanced Configuration System: Complex compatibility rules and variant management
3. Personal Garage: Save, compare, and manage multiple configurations
4. AI Integration: Intelligent assistance for configuration decisions
5. Enterprise Admin Panel: Comprehensive content and user management
6. Real-time Synchronization: Live updates across devices via Supabase Realtime

BUSINESS MODEL
--------------
- Direct-to-consumer luxury vehicle sales
- Configuration-based pricing with real-time calculations
- Order management and tracking system
- Dealer portal capabilities (future)

FRONTEND ARCHITECTURE

3.1 VEHICLE CONFIGURATOR
-------------------------
The configurator is the heart of the Volturiano platform, allowing users to
customize vehicles in real-time with dual visualization modes.

2D CONFIGURATOR MODE
- Technology: Pre-rendered WebP images from Blender
- Asset Count: 60+ images (5 paint colors × 3 rim colors × 4 angles)
- Location: web/src/assets/Configurator/volturiano/*.webp
- Viewer: web/src/viewers/two-d/Viewer2D.jsx
- Features:
  * Layered image composition
  * Smooth transitions between configurations
  * Angle switching (front-3q, side, rear-3q, rim)
  * Paint color selection (5 options)
  * Rim color selection (3 options)
  * Loading states and error handling
  * Image preloading and caching

3D CONFIGURATOR MODE
- Technology: React Three Fiber + Three.js
- Model: VolturianoGLB.glb (59MB, optimized GLB format)
- Location: web/src/assets/3DConfigurator/VolturianoGLB.glb
- Viewer: web/src/viewers/three-d/Viewer3D.jsx
- Features:
  * Real-time material color changes
  * HDRI environment lighting (studio_small_06_4k.exr)
  * Interactive camera controls (OrbitControls)
  * Geometric environment background
  * Shadow casting and receiving
  * Physically-based rendering (PBR) materials
  * Performance optimization (LOD, frustum culling)

CONFIGURATOR COMPONENTS
- Main Component: web/src/pages/Configurator/ConfiguratorNew.jsx
- Layout: web/src/features/configurator/components/ConfiguratorLayout/
- Header: ConfiguratorHeader (title, navigation)
- Panel: ConfigurationPanel (option selection UI)
- Canvas: ConfiguratorCanvas (2D) / Viewer3D (3D)
- Footer: PricingFooter (price display, save to garage)
- Controls: CameraControls (angle switching for 2D)
- Toggle: ViewModeToggle (switch between 2D/3D)

STATE MANAGEMENT
- Store: web/src/stores/configStore.js (Zustand)
- State Includes:
  * Selected vehicle ID
  * Manifest data (layers, variants, angles)
  * Selected options (optionId → valueId mapping)
  * Current camera angle
  * View mode (2D/3D)
  * Compatibility violations
  * Loading states
  * Pricing information
  * Vehicle options catalog

ASSET RESOLUTION SYSTEM
- Manifest System: JSON-based asset manifest defining layers, variants, angles
- Resolver: web/src/features/configurator/utils/assetResolver.js
- Path Resolver: web/src/features/configurator/utils/imagePathResolver.js
- Image Loader: web/src/features/configurator/utils/imageLoader.js
- Production Build: Uses import.meta.glob for asset bundling

COMPATIBILITY SYSTEM
- Rules Engine: web/src/features/configurator/logic/compatibility.js
- API Integration: checkCompatibility() function
- Violation Handling: CompatibilityAlert component
- Auto-resolve: Automatic option deselection for conflicts

PRICING SYSTEM
- Real-time Calculation: calculateConfigurationTotals()
- Base Price: From vehicle record
- Option Prices: Sum of selected option price_cents
- Currency Support: EUR (extensible)
- Display: PricingFooter component with formatted currency

The Garage is a comprehensive configuration management system where users can
save, organize, filter, and manage their vehicle configurations.

CORE FUNCTIONALITY

- Search: Full-text search across configurations
- Comparison: Side-by-side configuration comparison
- Sharing: Generate shareable links with QR codes
- Version History: Track configuration changes over time
- Timeline: Visual timeline of state transitions

GARAGE COMPONENTS
- Main Page: web/src/features/account/pages/Garage.jsx

- Lanes: GarageLane.jsx (one per state: Saved/Purchased/Prototype/Wishlist)

- Filters: GarageFilters.jsx (filter controls)
- Empty States: GarageEmptyState.jsx
- More Menu: CarCardMoreMenu.jsx (actions dropdown)

- Timeline: TimelineModal.jsx (version history viewer)

STATE MANAGEMENT
- Store: web/src/stores/garageStore.js (Zustand with persistence)
- Features:
  * Optimistic updates
  * Real-time synchronization via Supabase Realtime
  * Offline support with IndexedDB
  * Conflict resolution
  * Pagination and infinite scroll

DATABASE SCHEMA
- Table: garage_items
- Columns:
  * id (UUID, primary key)
  * user_id (UUID, foreign key to auth.users)
  * vehicle_id (UUID, foreign key to vehicles)
  * state (enum: saved, purchased, prototype, wishlist)
  * configuration (JSONB, full config data)
  * pricing (JSONB, pricing breakdown)
  * media (JSONB, images and thumbnails)
  * tags (text array)
  * share_code (text, unique)
  * created_at, updated_at (timestamps)
- Related Tables:
  * garage_item_tags (many-to-many tags)
  * garage_item_history (version history)
  * garage_item_shares (share tracking)

SHARING SYSTEM
- Share Codes: Unique alphanumeric codes (e.g., "ABC123")
- QR Codes: Generated client-side using qrcode.react
- Public View: SharedGarageView component (no auth required)
- Expiration: Configurable share expiration
- Analytics: Track share views and interactions

4.1 STATE MANAGEMENT ARCHITECTURE
-----------------------------------
Zustand stores for global state management with persistence and real-time sync.

USER STORE (userStore.js)
- Session Management: Supabase auth session
- Profile Data: User profile information
- Status Tracking: Loading, ready, error states
- Actions: setSession, setProfile, reset, fetchProfile
- Persistence: localStorage for session restoration

CONFIG STORE (configStore.js)
- Vehicle Selection: Current vehicle ID and base price
- Manifest Data: Loaded manifest with layers/variants
- Selected Options: Map of optionId → valueId
- Current Angle: Camera angle for 2D viewer
- View Mode: 2D or 3D
- Compatibility: Violations array
- Loading States: Manifest, options, pricing
- Actions: setVehicle, loadManifest, selectOption, setAngle, etc.
- Persistence: localStorage with hydration

GARAGE STORE (garageStore.js)
- Items: Array of garage items
- Filters: Current filter state
- Loading: Fetch states
- Real-time: Supabase Realtime subscription
- Actions: fetchItems, addItem, updateItem, deleteItem, setFilters
- Optimistic Updates: Immediate UI updates before server confirmation
- Conflict Resolution: Last-write-wins with version tracking

ADMIN STORE (adminStore.js)
- Admin Role: Current user's admin role
- Users: Cached user list
- Vehicles: Cached vehicle catalog
- Settings: System settings cache
- Actions: setAdminRole, fetchUsers, etc.

UI STORE (uiStore.js)
- Loading Overlay: Global loading state
- Force Overlay: Manual overlay trigger
- Actions: setForceOverlay, etc.

5. DATABASE SCHEMA & DATA MODELS
================================================================================

5.1 CORE TABLES
---------------

VEHICLES TABLE
- id (UUID, primary key)
- slug (text, unique) - URL-friendly identifier
- name (text) - Display name (e.g., "Tornado GT")
- base_price_cents (integer) - Base price in cents
- currency (text) - Currency code (EUR)
- hero_image_url (text) - Main vehicle image
- status (enum) - active, archived
- sort_order (integer) - Display order
- created_at, updated_at (timestamps)

VEHICLE_OPTIONS TABLE
- id (UUID, primary key)
- vehicle_id (UUID, foreign key) - Links to vehicles
- code (text) - Option code (e.g., "paint_orange_fury")
- label (text) - Display label
- description (text) - Option description
- category (text) - exterior, interior, performance, wheels
- price_cents (integer) - Option price in cents
- currency (text) - Currency code
- configurator_group (text) - Grouping for UI (exterior, interior, etc.)
- configurator_order (integer) - Display order
- configurator_visible (boolean) - Show in configurator
- configurator_image_url (text) - Option preview image
- configurator_metadata (JSONB) - Additional metadata
- created_at, updated_at (timestamps)

CONFIG_2D_MANIFESTS TABLE
- id (UUID, primary key)
- slug (text, unique) - Manifest identifier
- vehicle_id (UUID, foreign key) - Links to vehicles
- status (enum) - draft, published, archived
- version (integer) - Version number
- data (JSONB) - Manifest structure:
  {
    "metadata": {
      "defaultOptions": {...},
      "angles": ["front-3q", "side", "rear-3q", "rim"]
    },
    "layers": [
      {
        "id": "body",
        "zIndex": 1,
        "assets": {
          "blu-blue": {...},
          "nero-black": {...}
        }
      }
    ],
    "variants": [...]
  }
- created_at, updated_at, published_at (timestamps)

GARAGE_ITEMS TABLE
- id (UUID, primary key)
- user_id (UUID, foreign key to auth.users)
- vehicle_id (UUID, foreign key to vehicles)
- state (enum) - saved, purchased, prototype, wishlist
- configuration (JSONB) - Full configuration data
- pricing (JSONB) - Pricing breakdown
- media (JSONB) - Images and thumbnails
- share_code (text, unique) - Sharing code
- created_at, updated_at (timestamps)

GARAGE_ITEM_TAGS TABLE (Many-to-Many)
- garage_item_id (UUID, foreign key)
- tag (text) - Tag name
- Primary key: (garage_item_id, tag)

GARAGE_ITEM_HISTORY TABLE
- id (UUID, primary key)
- garage_item_id (UUID, foreign key)
- state (enum) - Previous state
- configuration (JSONB) - Previous configuration
- changed_by (UUID) - User who made change
- created_at (timestamp)

PROFILES TABLE (Extends auth.users)
- id (UUID, primary key, foreign key to auth.users)
- display_name (text)
- avatar_url (text)
- language_preference (text) - en, sv

5.2 ROW LEVEL SECURITY (RLS) POLICIES

- SELECT: Users can only see their own items

- DELETE: Users can delete their own items

VEHICLE_OPTIONS POLICIES
- SELECT: Public read access

CONFIG_2D_MANIFESTS POLICIES
- SELECT: Public read for published manifests
- INSERT/UPDATE/DELETE: content_admin or super_admin only

AUDIT_LOGS POLICIES
- SELECT: support_admin, content_admin, super_admin only
- INSERT: System (via Edge Functions)

7. SECURITY IMPLEMENTATION
================================================================================

7.1 AUTHENTICATION & AUTHORIZATION
------------------------------------

AUTHENTICATION
- Provider: Supabase Auth (JWT-based)
- Session Management: Secure token storage
- Password Security: Bcrypt hashing (Supabase managed)
- Email Verification: Required for account activation
- Rate Limiting: Built into Supabase Auth

AUTHORIZATION
- Role-Based Access Control (RBAC): 4 roles (user, support_admin, content_admin, super_admin)
- Route Protection: RequireAuth and RequireAdmin HOCs
- API Protection: RLS policies on all tables
- Admin Functions: Edge Functions with service role (server-side only)

7.2 ROW LEVEL SECURITY (RLS)
------------------------------

IMPLEMENTATION
- All User Data: Protected by user_id foreign keys
- Public Data: Vehicles, options (read-only for public)
- Admin Data: Audit logs, system settings (admin-only)
- Policies: Defined in SQL migrations

BEST PRACTICES
- Principle of Least Privilege: Users only access their data
- Admin Override: Admins can access all data (with audit logging)
- Service Role: Only used in Edge Functions (never client-side)

7.3 SECURITY HEADERS
--------------------
Location: web/vercel.json

HEADERS CONFIGURED
- X-Content-Type-Options: nosniff (prevents MIME sniffing)
- X-Frame-Options: DENY (prevents clickjacking)
- X-XSS-Protection: 1; mode=block (XSS protection)
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: Restricts browser features
- Content-Security-Policy: Restricts resource loading

CSP CONFIGURATION
- Default: 'self' (same origin only)
- Scripts: 'self' 'unsafe-inline' 'unsafe-eval' (for React)
- Styles: 'self' 'unsafe-inline' (for CSS Modules)
- Images: 'self' data: https: blob: (for images and data URIs)
- Connect: 'self' *.supabase.co *.supabase.in (for API calls)
- WebSockets: wss://*.supabase.co (for Realtime)
