### P2.4 Backend Hosting Decision for Production

CRITICAL ARCHITECTURE DECISION:

The Express server (web/server/index.js) runs as a long-running Node.js process
on port 3001. Vercel only supports serverless functions (max 10s default, 60s pro).
Your server has:
- Long-running sandbox operations (AI generation can take 60-300 seconds)
- WebSocket-like streaming (SSE for code generation)
- Background workers (submission-analyzer.js)
- Global state (sandboxState, activeSandboxProvider)

OPTIONS:
a) Keep backend on a separate hosting service (Railway, Render, Fly.io, VPS)
   - Frontend on Vercel, API on separate service
   - Change Vite proxy to point to production API URL
   - Add API URL as env var: VITE_API_URL
   
b) Restructure as Vercel Serverless Functions  
   - Major refactor, NOT recommended given sandbox architecture
   
c) Use Vercel with Edge Functions + external compute for sandboxes
   - Hybrid approach, complex

RECOMMENDATION: Option (a) — separate backend hosting. The sandbox operations
and SSE streaming require a persistent server.

### P3.4 Rate Limiting on All API Endpoints

Current status: NO rate limiting exists anywhere ❌

This is critical for:
- Preventing AI API abuse (each call costs money — Anthropic, OpenAI, Gemini)
- Preventing billing endpoint abuse
- Preventing brute force on auth-related endpoints
- Preventing webhook replay attacks

**File:** `web/server/index.js` [MODIFY]
**Package:** `express-rate-limit` [NEW DEPENDENCY]

#### P3.4.1 Rate Limit Tiers

| Tier               | Routes                                    | Limit             |
|--------------------|-------------------------------------------|--------------------|
| Strict             | /api/billing/*, /api/webhooks/*           | 10 req/min per IP  |
| AI Generation      | /api/generate-*, /api/enhance-prompt,     | 5 req/min per user |
|                    | /api/plan-website-*, /api/apply-ai-*      |                    |
| Standard           | /api/projects/*, /api/dashboard/*         | 30 req/min per IP  |
| Relaxed            | /api/component-catalog, /api/community/*  | 60 req/min per IP  |
| Open               | /api/health                               | No limit           |

#### P3.4.2 Implementation

```javascript
import rateLimit from 'express-rate-limit';

const strictLimiter = rateLimit({ windowMs: 60000, max: 10, message: { error: 'Too many requests' } });
const aiLimiter = rateLimit({ windowMs: 60000, max: 5, message: { error: 'AI generation rate limited' } });
const standardLimiter = rateLimit({ windowMs: 60000, max: 30 });
const relaxedLimiter = rateLimit({ windowMs: 60000, max: 60 });

// Apply to routes:
app.use('/api/billing', strictLimiter);
app.use('/api/webhooks', strictLimiter);
app.post('/api/generate-ai-code-stream', aiLimiter);
app.post('/api/enhance-prompt', aiLimiter);
// ... etc.
```
